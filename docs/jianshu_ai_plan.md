# 📚 鉴书灵 AI — 项目规划文档

> 用 6 年图书鉴别经验 + 视觉大模型，做一个"AI 鉴定师"。

---

## 🌱 项目起源

我（Hackingburg）在图书行业工作过 6 年，期间审核过超过 100 万本图书的正版/盗版。  
我已经做了一个微信小程序 **BookGuard（鉴书灵）**，目前的核心功能是：

- 用户扫描图书条形码
- 看到该书的"正版特征对照图"（封面、书脊、衬页、文字特写等 10 张左右）
- 用户自己肉眼对比手中的书，判断真伪

**痛点**：用户"看不懂"对照图，也不知道该重点看哪里 → 鉴别准确率受限。

**鉴书灵 AI 要做的事**：让 AI 来当"鉴定师"，直接告诉用户这本书有多大概率是盗版 + 为什么。

---

## 🎯 产品定位

> **"图书行业的反盗版基础设施"** —— 服务读者（C 端） + 服务出版社（B 端）。

### 核心价值
- **对读者**：花 3 秒拍照 → 得到专业级鉴定报告
- **对出版社**：保护正版权益，可作为反盗版工具与执法辅助
- **对行业**：把"100 万本盗版书的鉴别 know-how" 沉淀成 AI 能力

### 护城河
- 6 年一线鉴别经验（无法被快速复制）
- 已有正版样本图库（每本书 10 张以上特征图）
- 对盗版商造假手法的深度理解（拍样本时主动考虑"盗版商会怎么仿"）

## 🏗️ 技术架构

```
┌─────────────────────────────────────────────────┐
│            👤 用户的微信小程序                    │
│         （现有鉴书灵前端，几乎不动）              │
└────────────────────┬────────────────────────────┘
                     │ HTTP
                     ↓
┌─────────────────────────────────────────────────┐
│      🛠️ cool-admin 后端（Node.js / TS）          │
│      （现有代码 + 加 1 个新接口）                 │
│                                                  │
│  POST /api/book/ai-verify                       │
│    → 转发给 AI 服务                              │
└────────────────────┬────────────────────────────┘
                     │ HTTP 内部调用
                     ↓
┌─────────────────────────────────────────────────┐
│      🤖 AI 鉴别服务（Python / FastAPI）          │ ← 新增
│      （复用 llm-learning-journey 的能力）         │
│                                                  │
│  调用视觉 LLM（Qwen-VL / GLM-4V）                │
│  对比正版样本 vs 用户照片                        │
│  返回结构化鉴定报告                              │
└─────────────────────────────────────────────────┘
```

### 选型决策记录

| 决策点 | 选择 | 理由 |
|--------|------|------|
| AI 引擎 | **Qwen-VL（通义千问视觉模型）** | API 调用简单 / 中文场景强 / 新用户免费额度足够 MVP / 1 天能跑通 |
| 后端服务 | **新建 Python FastAPI 服务** | 复用 4 个月 LLM 学习成果 / 与 cool-admin 解耦 / 未来可独立对外提供 API |
| 是否重写小程序 | **不重写**，沿用 cool-admin | 现有功能继续工作，零迁移成本 |
| MVP 范围 | **AI 比对 2 张图返回判断** | 最小可验证单元 |

## 💡 鉴别维度（来自 6 年实战经验）

这是我审 100 万本书总结出的盗版常见破绽 —— 也是 AI 要重点关注的维度：

### 1. 文字层面
- **文字边缘锯齿** ⭐ 最常见 —— 喷墨打印输出 vs 胶印的差异
- 文字粗细不均
- 油墨晕染
- 字体被替换（盗版商找不到原字体，用相似字体替代）

### 2. 装帧层面
- **书脊烫金 / 烫银工艺缺失** ⭐
- 精装本的封面纸张厚度
- 衬页装订工艺
- 裁切边缘整齐度

### 3. 印刷层面
- **色彩饱和度差异** ⭐
- 网点结构（盗版常见过粗 / 失真）
- 暗部细节丢失
- 反差不自然

### 4. 用纸层面
- 纸张白度
- 纸张厚度（克数）
- 纸张反光（盗版常用更便宜的反光纸）

## ⚠️ 风险与应对

### 风险 1：版权问题
- **问题**：我拍的正版样本图属于"复制"，理论上有版权风险
- **应对**：提前主动联系出版社谈合作，把自己定位为"反盗版伙伴"而非"对手"
- **优先合作对象**：理想国、新经典、读库等中型独立出版社（盗版痛点最深、决策链短）

### 风险 2：AI 准确率不达标
- **问题**：视觉 LLM 在某些细节判断上可能出错
- **应对**：MVP 阶段不追求"100% 准确"，给出"置信度 + 理由"让用户辅助判断；同时收集错判样本，持续优化 Prompt

### 风险 3：盗版商家也用 AI 反向优化
- **问题**：如果工具公开，盗版商会拿来检测自己的盗版"破绽够不够小"
- **应对**：核心鉴别维度不公开 / 关键样本对出版社独家 / 持续更新检测策略
